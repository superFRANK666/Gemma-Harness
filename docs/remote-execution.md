# 远端执行与桌面会话

Harness 将模型推理和工具执行分别配置。主控 GUI 运行 agent 循环；执行设备只提供文件、命令、浏览器和原生桌面工具，不在远端启动第二个 agent。模型可以在本机、LM Studio 或另一台推理服务器上运行，执行设备可以独立选择。工具结果会进入所选模型的上下文。

## 从 GUI 连接

1. 在执行设备上打开桌面应用，在「设置与连接 → 执行设备」选择本机工作目录。
2. 在「将本机作为执行设备」填写主控能访问的 `wss://设备地址:45455`，然后点击「启动与生成配对串」。默认监听 `0.0.0.0:45455`；界面的 `127.0.0.1` 示例地址只适合本机测试，跨设备需要改为执行设备的局域网或 VPN 地址。
3. 在主控的同一设置页粘贴配对串，点击「校验证书并配对」。选择该执行设备，点击「读取设备共享目录」，保存设置后新建会话。
4. 模型连接在「模型连接」页独立选择。原生桌面控制在主控「工具与扩展」中启用，并在执行设备本机完成所需操作系统授权及能力检查。浏览器组件也在执行设备本机安装。

连接需要主控能够直达执行设备的 TCP 端口。当前实现没有公网中继、NAT 穿透、云端调度或自动 SSH 隧道；可使用已有局域网、VPN 或自行管理的端口转发。原生桌面功能针对执行设备当前登录的图形会话，不能将无图形会话的服务器变成桌面。

会话固定绑定执行设备与该设备实际共享的目录。新建远端会话及执行远端工具时都会核对宿主报告的目录；宿主更换共享目录后，旧会话会明确拒绝执行，需要重新建立绑定。远端路径由远端操作系统解释。stdio MCP 仍运行在主控，不会被冒充为远端工具。

启动执行设备服务授权已配对主控使用该宿主的执行器。主控的工具开关约束该主控的请求，当前宿主没有按配对凭据细分的工具 ACL。文件 API 检查共享目录边界；终端运行真实系统 Shell，不能将工作目录视为 Shell 或桌面的安全沙箱。

## 配对和传输

协议版本为 `1`。传输仅使用 WSS，每个文本帧是一条带 `jsonrpc: "2.0"` 的 JSON-RPC 请求或响应，消息上限为 32 MiB。当前操作进度通过状态查询和可轮询的持久事件游标恢复，不使用服务端推送通知。

执行设备首次启动时生成自签名 TLS 证书和私钥，并持久保存。客户端将配对串携带的证书 SHA-256 指纹作为精确信任锚，仍验证 TLS 握手签名；不依赖公共 CA。证书指纹变化会拒绝连接，需要核实设备后重新配对。证书和私钥必须匹配，缺失其中之一会拒绝启动。

配对串格式为 `harness-pair:v1:<base64url-json>`，包含 `protocolVersion`、`url`、`certificatePin`、`secret`、`expiresAt`。`secret` 是操作系统随机源生成的 256-bit 随机值，邀请五分钟有效，只能成功使用一次。完整配对串拥有配对能力，不应放入日志或提交到仓库。

配对成功后发放独立随机长期令牌。宿主只保存其 SHA-256 摘要；主控将令牌存入操作系统凭据库，设置中只保留设备公开信息。每个已认证连接的后续请求仍检查撤销状态。

| RPC 方法 | 参数与行为 |
| --- | --- |
| `pair` | `{protocolVersion, secret}`；返回宿主身份、地址、证书指纹与令牌 |
| `authenticate` | `{protocolVersion, token}`；确认宿主身份与实际共享目录 |
| `capabilities` | 返回设备、平台、共享目录、执行器能力与桌面租约要求 |
| `operation.execute` | `{operationId, name, args}`；持久接收操作后返回状态，执行在宿主继续进行 |
| `operation.status` | `{operationId}`；返回状态、结果、错误与时间信息 |
| `operation.cancel` | `{operationId}`；请求取消，不能撤回已送达的桌面输入 |
| `events.after` | `{cursor, operationId?}`；按游标返回最多 256 个操作状态／输出事件和下一游标，可按操作过滤 |
| `desktop.lease` | `{action, sessionId}`；`action` 为 `acquire`、`renew` 或 `release` |
| `artifact.fetch` | `{path}`；只读取宿主专用 artifacts 目录中的文件，最大 16 MiB；返回 base64、MIME、SHA-256、字节数和设备来源 |

客户端的 `PairedDevice.id` 是稳定的宿主 ID。执行设备状态页 `pairings[].id` 是每个配对凭据的 ID，用于单独撤销；二者含义不同。主控「移除设备」删除本机保存的连接，宿主「撤销并停止」才会在执行设备撤销该凭据。

## 操作去重与崩溃恢复

宿主使用 SQLite WAL 与 `synchronous=FULL` 保存操作。通常状态为 `accepted → dispatching → completed/failed/cancelled`；在执行副作用前，先持久写入 `dispatching`。

同一配对凭据重发相同 `operationId` 和参数，得到已有状态或结果，不再次执行。相同 ID 携带不同参数或目录会拒绝；另一配对凭据不能查询或接管该操作。客户端断线重连时保留原操作 ID，并可用状态查询及事件游标恢复，不应另生成 ID 盲目重试。

宿主重启时，未结算的 `accepted` 或 `dispatching` 操作变成 `indeterminate`，不会自动重放。它表示无法确定副作用是否已经发生，需要先检查实际文件、进程或桌面状态。去重不能提供系统崩溃期间任意 Shell 副作用或键鼠输入的 exactly-once 保证，也不能撤销已有副作用。

文件修改另外使用预期 SHA-256 检查当前内容。操作结果和完整 artifacts 保留在宿主；状态页仅返回最近操作的精简元数据，避免每次刷新重新传送历史截图。

终端 stdout／stderr 在进程退出前即可通过事件游标读取；预览合计 32 KiB，达到限额后明确提示截断，完整输出保留为 artifact。SQLite schema v1→v2 自动迁移保留既有事件。主控若在传输错误后仍无法确认操作状态，会停止本轮并跳过后续调用，不将换一个 ID 当作自动重试。

## 一个图形会话中的桌面工作流

每个宿主同一时刻只允许一个 Harness 桌面工作流持有租约。租约同时绑定已认证配对凭据和稳定会话 ID，持续 60 秒；主控在模型思考期间每 20 秒续租，在任务结束时释放。另一个会话或另一主控不能抢占仍有效的租约。

远端 `desktop_*` 操作必须带有主控注入的保留参数 `__harness_session_id`。宿主核对租约所有权后移除该参数再交给执行器，操作摘要也绑定配对与会话，防止更换会话重放。原生 helper 继续检查当前观察的 `snapshot_id` 和元素引用，过期观察会拒绝。

租约过期、释放、撤权、停止全部任务或停止服务时，会清除租约并请求取消相应桌面操作。状态页的 `desktopLease` 显示持有者和剩余时间。租约仅协调 Harness 工作流，不能阻止人类或其他程序操作桌面；动作后仍需重新观察、验证结果。

执行设备 GUI 可使用「停止设备上的全部任务」「撤销并停止」或「停止服务」收回控制。停止操作会请求取消终端及桌面工作；已经输入的文本、点击或其他副作用不会回滚。能力检查缺失操作系统权限时会显示实际错误，不会生成替代截图。

## 验证范围

`cargo test --workspace --exclude harness-desktop` 覆盖协议、实际 localhost WSS、错误证书 pin、邀请复用拒绝、去重与冲突、事件恢复、持久身份与崩溃标记、撤权、命令取消，以及跨配对／跨会话租约拒绝、释放和到期行为。核心端到端测试使用脚本化 HTTP 模型和真实文件／进程执行器，不代表目标 GGUF 的真实能力认证。

桌面租约测试使用无副作用的未知工具验证准入边界，不向操作系统发送鼠标键盘输入。真实跨电脑连接、各平台桌面权限和应用控制，需要在对应设备上另行验收。自动测试中的浏览器下载用例默认忽略，避免普通测试隐式下载 Chromium。
