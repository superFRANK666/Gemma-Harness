# Gemma 适配与验证

本文记录 Harness 对不同 Gemma 模型和推理后端的处理，以及可复现验证的方法。模型家族按名称自动识别只是提示；实际能力取决于具体权重、量化、模板、推理服务和视觉 projector，必须在实际部署上重新诊断。

## 配置与行为

- 「模型连接」可指定 Gemma 4、Gemma 3、Gemma 3n、FunctionGemma 或其他家族，以及 llama.cpp、LM Studio 或其他后端。托管引擎结合 GGUF 架构、名称和文件名推测系列，避免将采用 Gemma 3 架构的 FunctionGemma 直接认成普通 Gemma 3；信息冲突或不足时保持未知。CodeGemma 不归入 Gemma 3。名称和元数据都不是权重认证。更改相关连接配置或重启托管引擎会使旧诊断失效。
- 本地引擎可显式选择 UTF-8 Jinja 模板；留空继续使用 GGUF 内嵌模板。选择文件时先生成按 SHA-256 命名的输入快照，并在模型运行配置中记录来源和摘要，不修改原文件，也不声称后端已经实际应用。发现已知旧模板过滤工具参数名的源码模式时会提示；源码模式只是线索，应结合实际渲染和工具调用诊断。切换模板后需要重启引擎并重新诊断。
- 托管引擎诊断会读取启动日志的前 1 MiB，仅报告已知的 Gemma 4 旧模板兼容处理及控制 token 类型覆盖警告，不复制原始日志；读取失败和截断会明确标识。外部服务的运行时日志不可见时，不能推断没有此类警告。
- Gemma 4 + llama.cpp 的 Chat Completions 诊断会向 `/apply-template` 发送不含用户数据的合成声明和工具结果，检查 `type`、`description`、嵌套字段及结果标记是否保留。仅在服务端报告唯一且匹配的模型时使用该检查；不支持或身份不明确时显示未知。若 `/props` 可用，还会显示服务端报告的默认采样值和模板表示的摘要，不输出模板内容；服务端可能规范化模板，且默认值不证明单次请求的实际生效值。渲染通过不代表模型会正确调用工具。
- 显式启用／关闭思考仅支持 Gemma 4 + llama.cpp + Chat Completions；自动模式不覆盖后端默认值。诊断单独报告是否在工具探测中观察到推理内容，未观察到不代表一定已关闭思考。输出 token 上限可配置，输入预算相应保留空间。
- 采样设置可以显式请求 temperature、top-p、seed；top-k 和 min-p 仅用于 llama.cpp Chat Completions。留空遵循服务默认值，诊断显示请求值而不声称后端一定应用。设置中提供 Google 的 Gemma 4 对照值 `temperature=1.0, top_p=0.95, top_k=64` 并额外将 min-p 设为 0，也提供可选的贪心对照 `temperature=0, top_p=1, top_k=1, min_p=0`；它们均不保证工具调用，社区衍生权重仍应独立评测。显式设置的输出上限不会被自动提高；自动预算下，Gemma 4 思考生成达到上限且尚无可见正文时，可在未执行该次工具调用的前提下增加预算重试一次。
- Gemma 4 在已收到工具结果后若返回空答案，可进行一次不提供工具的结果说明重试；之前的工具不会重放。首次生成直接为空、再次为空或结果不明确仍会报告未完成。
- FunctionGemma 的原生函数标记只在完整接收后解析，格式不完整、重复参数或不安全的控制标记会被拒绝。llama.cpp 所需的原生参数格式仅用于传输；内部和历史仍保存标准 JSON。结构化调用和原生调用不会混合执行。FunctionGemma 专门面向函数选择，不应当作通用编码 Agent；复杂参数、多步计划和最终答案应分别测试。
- 工具批次必须全部通过工具名称和原始 schema 校验才执行；可纠正的完整无效批次最多连续重试一次，中断或截断的流绝不执行。已保存的工具调用诊断若明确失败，每轮会提示以实际工具事件为准。Gemma 4 本轮没有工具执行事件、最终文本或生成失败前的可见文本却提及已提供的工具名称时，也会明确提示该事实；它不判断模型的意图，也不能识别所有虚构表述。读取文件返回绑定文件版本的 `read_token`，可代替长 SHA256 用于修改；模型省略版本时，Harness 仅能补全本轮对同一路径实际读取到的令牌，并在事件中记录有效参数与来源。底层仍校验路径和文件哈希；令牌过期、文件变更或读取发生在上一轮时必须重新读取。
- 正常结束的界面状态显示「回复已结束」，仅表示该轮回复结束，并不保证用户要求的文件任务已经完成；发现上述未执行工具提示时显示「需要核对」。实际结果应以工具活动和文件内容为准。
- Gemma 4 若在修改或删除时编造了不存在的版本令牌，执行器会先拒绝操作。对于本轮确实读过或检查过的相同路径，修改失败会返回已取得的令牌；删除失败后会暂时简化本轮提供给模型的删除参数，并提示由程序绑定检查过的版本。模型必须重新决定是否调用；程序不会悄悄替换错误参数并执行，重试仍需通过文件版本核验。用户指定的 SHA-256 参数仍可使用。
- JSON 字符串参数中的重复键会被拒绝；浏览器／桌面动作在执行前检查动作所需字段。`tool_search` 的 `keep` 可保留最多五个当前已加载的可选工具，包含新搜索结果在内仍最多六个。重复三次相同且未变化的只读观察会收到提示，但不会阻止有意轮询。
- Gemma 4 的任务提示建议对已有文件的局部修改优先使用精确补丁，避免不必要地重写其他字节。模型仍可能选择整文件写入，必须核对实际工具调用和结果。
- `file_write` 省略版本时仅创建新文件，已有目标不会被覆盖；显式 `expected_sha256:null` 仍可用。新文件以不覆盖目标的原子链接方式发布，如果文件系统不支持这种方式会报错，不退回覆盖式写入。
- 常用文件操作包含读取、创建、修改、搜索和删除。普通读取适用于不超过 2 MiB 的 UTF-8 文件；更大的文件和二进制文件可通过 `tool_search` 加载 `file_read_chunk` 分段读取。分页偏移按字节计算，后续读取需要沿用同一版本令牌；如果内容为了适应模型上下文被缩短，返回的下一偏移以模型实际收到的内容为准。写入和精确替换支持最大 16 MiB 的文件，二进制写入使用 base64。文件状态检查、分段读取和删除后恢复工具按需加载，以节省模型上下文。
- 删除工具只处理工作区内的普通文件，不删除目录或最终路径为符号链接的文件；操作前核对文件版本并保存备份。备份保存失败时不会删除。删除完成后可展开该操作的活动记录，点击「恢复删除的文件」；恢复使用原设备和记录中的备份，目标位置已有文件时不会覆盖。备份会占用磁盘空间；不支持硬链接的文件系统可能无法执行创建或恢复。检查文件状态或读取部分片段并不等同于完整读取，不能据此自动授权覆盖整个已有文件；对已看到的片段使用精确匹配的局部修改仍可获得同轮版本令牌。
- 大量文本通过 artifact 分页，偏移量为 UTF-8 字节位置，使用返回的 `nextOffset`；读取预览被截断时应跟随 `full_text_artifact`。命令输出超过 artifact 限额时明确报告不完整，不把有限内容描述为完整输出。
- 视觉输入要求图片输入及图片工具结果两项诊断通过。Gemma 4 的简单图文请求投影将图片放在文字前；多段交错的图片说明保持原有顺序，历史仍保存为本地 artifact 引用。明确提到先前图片的后续消息可在当前用户轮次恢复最近图片，避免压缩时将图片和问题拆开；仍受每轮最多两张、总计 8 MiB 和视觉复验限制。外部端点每轮首次发送图片前重新验证；色块或工具选择的语义探测失败可重试一次，传输失败不会无限重试。失败时图片留在本地且不传输。
- 临近输入预算时，文本请求可使用 llama.cpp 实际 `/apply-template` 与 `/tokenize` 计数，前提是 Chat Completions 后端能报告唯一且匹配的所选模型；可信计数使用较小但非零的安全余量。带图请求、端点不支持或模型身份不明确时，回退到带视觉余量且标记为估算的计数。压缩和溢出恢复会按顺序保留被省略的用户消息，摘要遗漏不会删除这些纠正；若用户消息本身超出保护或上下文预算则明确停止。
- `file_search` 对不超过 64 MiB 的大 UTF-8 文件使用流式搜索；超过上限、单行超过 256 KiB、非 UTF-8 或无法读取时会标明遗漏。只有 `complete:true` 才能在报告范围内把无匹配当作完整结果。Gemma 4 显式使用 `raw:true` 读取短文件时向模型直接返回原文；普通读取仍返回带行号的视图。版本信息仍保留在活动记录，并用于本轮后续修改的版本校验。

## 复现真实模型测试

先自行启动目标推理服务，按实际情况修改下列变量；测试会向该服务发送合成指令和图片，不需要用户文件。工具参数评测不执行工具；Agent 评测仅在全新临时工作区执行文件操作，并禁用终端、浏览器、桌面和 MCP。诊断使用合成彩色图片，只证明本次探测，不证明所有图片和任务都可用。

```sh
export HARNESS_EVAL_URL=http://127.0.0.1:8080
export HARNESS_EVAL_MODEL=your-loaded-model-id
export HARNESS_EVAL_BACKEND=llama_cpp  # auto、llama_cpp、lmstudio、other
export HARNESS_EVAL_FAMILY=gemma4      # auto、gemma4、gemma3、functiongemma、other
export HARNESS_EVAL_THINKING=off       # auto；Gemma 4 + llama.cpp 可用 on/off
export HARNESS_EVAL_REPEATS=3
# 可选：只运行指定案例（工具与 Agent 评测的案例名各不相同）
export HARNESS_EVAL_CASES=english_string,nested,multi_tool_selection,no_tool
# 可选：显式采样和输出预算；不设置时遵循服务默认值
export HARNESS_EVAL_TEMPERATURE=1.0
export HARNESS_EVAL_TOP_P=0.95
export HARNESS_EVAL_TOP_K=64
export HARNESS_EVAL_MIN_P=0
export HARNESS_EVAL_SEED=42
export HARNESS_EVAL_MAX_OUTPUT=2048

cargo run --release -p harness-model --example gemma_tool_eval > tool-results.json
# 运行 Agent 评测前清空或替换 HARNESS_EVAL_CASES，避免使用工具评测专用案例名
unset HARNESS_EVAL_CASES
export HARNESS_EVAL_CASE_TIMEOUT_SECONDS=240 # 可选，慢速 CPU 的单个 Agent 用例上限
cargo run --release -p harness-core --example gemma_agent_eval > agent-results.json
cargo run --release -p harness-model --example gemma_diagnose > diagnosis.json
```

如服务需要认证，工具评测可通过 `HARNESS_EVAL_API_KEY` 注入密钥；不要把密钥或含敏感请求的输出提交到仓库。工具评测覆盖多工具选择，并在思考模式下将工具调用期间的思考内容带回；Agent 评测按字节比较精确输出并覆盖 CRLF 与无需工具的反例。运行次数范围为 1–10，固定 seed 便于复现但不代表随机采样统计；应使用多个 seed 和真实任务复测。诊断可能发现模型不支持视觉或工具回灌，这是实测结果而不是自动修复。

本次所用模型文件的固定 revision、SHA256、后端版本、逐项合成测试结果和限制见 [2026-11-10 机器可读验证记录](gemma-adaptation-verification-20261110.json)，更早测试见 [2026-11-09 验证记录](gemma-adaptation-verification-20261109.json)。E2B 在精确复述文件的尾部换行和 CRLF 上仍有失败；FunctionGemma 的复杂参数和通用 Agent 场景也有明显局限。视觉诊断存在通过与失败样本，色块探测不代表桌面任务准确率。每个模型的实际量化、模板、projector 和部署环境均需独立复测。

目标 26B Heretic 的 `IQ1_S` 权重在本机 4K、CPU、无 projector 的小样本中未通过工具诊断，另外三个合成案例均未通过；需要工具的两个案例生成了声称调用工具的文本，但没有发出可执行调用。llama.cpp 同时报告内嵌 Gemma 4 模板较旧并启用兼容处理。该结果只适用于本次组合，不能确定失败原因，也不能代表其他量化；应检查工具调用、尝试适合硬件的其他量化和匹配模板，并配置 projector 后单独复测视觉。

针对该权重的 [模板渲染对照](gemma-26b-template-audit-20261110.json) 使用同一 llama.cpp 版本和仅包含 GGUF 元数据的稀疏测试文件，未运行推理。内嵌模板在合成用例中遗漏部分与 schema 关键字同名的参数，模型源仓库和 Google 模板保留这些参数；简单天气工具请求的三种渲染完全一致，因此该模板差异本身不能解释此前简单调用的失败。

如果需要手动复现模板对照，可从[目标模型源仓库的固定版本](https://huggingface.co/llmfan46/gemma-4-26B-A4B-it-ultra-uncensored-heretic/blob/f5970e2eee74ef654b7ee97722b3e67a7ec6adda/chat_template.jinja)或 [Google Gemma 4 26B 的固定版本](https://huggingface.co/google/gemma-4-26B-A4B-it/blob/4d7ae4984b7db7de8f8457170b3f1a419ee76d52/chat_template.jinja)取得 Jinja 文件，在「本地引擎」中显式选择并重启，然后运行诊断。两个原始文件的 SHA-256 分别为 `0a52be69cda5ab8aeb627d6ff51a7b34c7d06afabb6b0f00cf8ee63df16a6315`、`ae53464bf3be25802b3a5b37def7fd89667067d7577049b3b2d74c4d8de4c6d4`；服务报告的模板表示可能因为空白字符规范化而有不同摘要。该操作修复上述渲染缺陷，不保证权重能够正确选择或执行工具。

### 2026-11-10：26B 实际模型对照

使用已完整校验 SHA-256 的同源 `IQ1_S` 和 `IQ2_XXS`，在 macOS arm64、16 GiB、llama.cpp b12211、CPU 4 线程、4K 上下文、请求关闭思考并关闭提示词缓存的条件下，运行六项合成工具测试。输出限制为 128 token，测试包括严格的无需工具反例和工具结果回灌；命中上限只代表该次生成未完成。下表为 seed 42 的结果，随机采样列请求 `temperature=1, top_p=0.95, top_k=64, min_p=0`；服务没有逐请求回显实际生效值：

| 量化 | 模板 | 采样 | 通过 |
| --- | --- | --- | --- |
| IQ1_S | GGUF 内嵌 | 随机采样 | 0/6 |
| IQ1_S | Google 固定版本 | 随机采样 | 0/6 |
| IQ1_S | Google 固定版本 | 贪心 | 2/6 |
| IQ2_XXS | GGUF 内嵌 | 随机采样 | 3/6 |
| IQ2_XXS | Google 固定版本 | 随机采样 | 2/6 |
| IQ2_XXS | Google 固定版本 | 贪心 | 3/6 |
| IQ2_XXS | 模型源仓库固定版本 | 贪心 | 3/6 |

Google 模板与随机采样下，seed 43 和 44 的六项结果分别为 IQ1_S 的 2/6、2/6 和 IQ2_XXS 的 1/6、4/6，说明结果受种子影响，不能仅按 seed 42 认定某个量化稳定更优。IQ2_XXS 的四项子集仅将 min-p 从 0 改为 0.05 时，两组均为 1/4；这不证明该参数对其他任务无影响。单独向后端强制要求调用时，中文样本产生了参数类型错误，因此没有将强制调用作为自动回退。

IQ2_XXS 在 Google 模板和模型源仓库模板下分别运行了三个真实 Agent 案例，均为 1/3：无需工具的反例通过，文件读取和创建失败。模型源模板的一次读取测试中，模型没有产生工具事件却声称读取并编造了内容；加入基于事件的提示后，真实模型重跑触发了提示，文件任务仍然失败。完整配置、权重与模板摘要、逐项输出和局限见 [26B 模型对照记录](gemma-26b-model-comparison-20261110.json)。这些小样本不能区分所有量化、转换和衍生权重影响；没有测试视觉 projector。

### 2026-11-10：文件操作与真实模型复测

在 macOS arm64、16 GiB 内存、llama.cpp b12211、4K 上下文中，使用已核对 SHA-256 的同一 Heretic 模型 `IQ3_XXS` 量化、模型源模板、关闭思考和固定贪心采样，对真实 Harness 进行隔离文件任务测试。最终一轮使用提示缓存、每项 480 秒上限，八次测试通过六次：创建、修改、同一删除任务的两次独立运行、中文「只读取，不删除」以及无需工具的回答。两次删除均核对了文件消失和备份字节；精确读取时模型遗漏了末尾换行，而「只解释、不要操作」没有修改文件但生成未正常结束。两次删除使用同一提示和 seed，不能当作覆盖多种任务的可靠性统计。

测试还发现 Gemma 有时会在隐藏版本信息的原文读取后猜测删除令牌；没有恢复提示时，错误令牌被拒绝，模型可能反复出错。调整提示并在错误后缩减本轮删除参数后，仍需模型自行重试，执行器继续校验同轮文件版本。一项强制结构化输出的独立实验在仅需解释的提示中选择了删除，因而没有接入产品，也没有执行该实验选出的动作。逐项结果、不同测试阶段、量化文件摘要和局限见 [文件操作验证记录](gemma-file-operations-verification-20261110.json)；这些结果不能保证其他提示、量化或设备上的行为。

## 2026-11-09 实测摘要

测试运行于 macOS arm64、16 GiB 内存、llama.cpp b12211、8K 上下文和单推理槽。模型文件和视觉 projector 均在本机计算 SHA256；服务的模型别名本身不能证明权重身份。

- [Gemma 4 E2B Q4_0](https://huggingface.co/ggml-org/gemma-4-E2B-it-GGUF/tree/main)：固定的 11 项工具评测，思考开／关各 11/11。关闭思考的三轮隔离 Agent 测试共 8/12：修改和查找各 3/3，创建 2/3，精确读取 0/3。开启思考的单轮测试为 3/4，失败项是写入时丢失原文件末尾换行。另一次关闭思考的单轮测试为 2/4。文件状态正确不保证模型的中间陈述正确。
