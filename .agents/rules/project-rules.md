# Harness 项目规则

## 1. Git 提交与远端推送
- 本项目远端 GitHub 仓库为 `https://github.com/superFRANK666/Gemma-Harness`（`origin`）。
- 每次完成代码或项目文件修改并完成必要验证后，必须及时执行 `git commit` 并 `git push` 推送到远端仓库 `origin`。
- 提交前检查 `git status` 与变更范围，避免混入无关文件、临时缓存或敏感信息，确保提交信息清晰准确。

## 2. 代码、框架与算法质量标准
- **最佳性能与最简洁写法**：在架构设计、框架组织与算法实现上追求最优性能（时间与空间复杂度、资源开销）与最简洁清晰的表达方式。
- **杜绝“屎山代码”**：严禁复制粘贴式重复逻辑、打补丁式的特判堆砌、混乱耦合、过深嵌套、无用死代码以及无意义的过度封装；保持模块与函数职责单一、逻辑清晰、可维护性强。

## 3. 编辑后自我审视与精进
- 每一次编辑完成后，主动回顾本次修改，思考是否还有可以进一步提升的空间（例如更优的算法/数据结构、更精简的结构、更低的耦合或更好的边界处理）；确认当前已达到简洁且高质量的状态后，再完成最终收尾、提交并推送。
